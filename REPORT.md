## 4 балла: один контейнер

Образ собран командой `docker build -t ipr-hw3:local .`.
Контейнер запущен с публикацией `8082:8000` и переменной
`GREETING=Привет из одного контейнера!`.

| Проверка | Фактический результат |
| --- | --- |
| Первый `GET /` | HTTP 200, `count: 0`, `storage: sqlite`, заданное приветствие |
| Первый `POST /increment` | HTTP 200, `count: 1` |
| Второй `POST /increment` | HTTP 200, `count: 2` |
| Повторный `GET /` | HTTP 200, `count: 2` |
| `docker logs` | Строка запуска `listening port=8000 storage=sqlite` и записи запросов |

## 6 баллов: Compose и именованный volume

Использован `compose.sqlite.yaml`, внешний порт `8081` и приветствие
`Привет из SQLite!`. Именованный volume `sqlite-data` подключён к `/data`.

Выполнены три POST-запроса: счётчик изменился с `0` до `3`.
Затем выполнены `docker compose ... down` и `docker compose ... up -d --wait`.
Идентификатор контейнера приложения изменился, а `GET /` вернул прежний
`count: 3` и то же приветствие. Следовательно, данные сохранились вне контейнера.

## 8 баллов: отдельный Redis

Использован основной `compose.yaml`. Оба сервиса успешно прошли healthcheck.
Для приложения заданы `STORAGE=redis` и `REDIS_URL=redis://redis:6379/0`.

Подтверждены настройки Redis:

- `docker inspect` показал именованный volume, подключённый к `/data`.
- `redis-cli CONFIG GET appendonly` вернул `appendonly` / `yes`.
- `HostConfig.PortBindings` Redis равен `{}`: порт Redis не опубликован.
- Публикуется порт приложения `8080:8000`.

### Сохранение данных после удаления контейнеров

Первый GET вернул `count: 0`, три POST-запроса увеличили значение до `N = 3`.
После `docker compose ... down` и повторного `up -d --wait` оба контейнера
созданы заново. `GET /` вернул `count: 3`; значение сохранено в volume Redis.

### Отключение и возвращение Redis

После `docker compose ... stop redis` получены следующие ответы:

| Запрос | Код | Тело ответа |
| --- | --- | --- |
| `GET /healthz` | 200 | `{"status": "alive"}` |
| `GET /readyz` | 503 | `{"error": "storage_unavailable"}` |
| `POST /increment` | 503 | `{"error": "storage_unavailable"}` |
| `GET /` | 503 | `{"error": "storage_unavailable"}` |

Контейнер приложения остался `running`, а healthcheck стал `unhealthy`.

После `docker compose ... start --wait --wait-timeout 120 redis` приложение
снова стало `healthy`. Первый `GET /` вернул `count: 3`, следующий POST —
`count: 4`. Ошибочный POST во время сбоя не увеличил счётчик.

Контейнер приложения до отключения Redis и после восстановления совпадает:
`a88c2570df467520b7f47713529bb4029afa7a800843084b6771df8b872e456d`.
Время запуска осталось `2026-11-18T17:41:35.797251816Z`, `RestartCount` остался `0`.
Приложение восстановило работу без перезапуска.
